local data, clearly explained

Lock In needs limited browsing activity to provide its site-blocking and daily-allowance features.

  • It reads the hostname of the active tab and, when it matches a configured URL rule, its path, query, and fragment, never page content.
  • It stores your zones, schedules, and usage totals in the protected local Lock In watchdog.
  • Nothing is transmitted, sold, shared, or used for advertising or profiling.

No browsing data is handled until you choose Accept and continue. Read the full privacy policy.

super-strict mode, start to finish

Loaded from the repository, Lock In is a dashboard and a sensor: it draws your day and watches the active tab, but nothing outside the browser is stopping you. These three steps move every decision to a Windows task the browser cannot switch off.

  • Scheduled zones and spent allowances become Brave/Chrome URLBlocklist policy, applied by Windows rather than by the extension.
  • Always-allowed pages stay open through the matching URLAllowlist and never spend allowance.
  • If the browser is running and the sensor disappears for 30 seconds, every enabled zone is blocked and the browser loses outbound network access until Lock In reports back.
  • Zones, usage and enforcement state move to C:\ProgramData\LockIn, owned by SYSTEM. Only the Windows accounts you name can configure them.
  • Windows 10 or 11
  • Brave or Chrome
  • one UAC prompt
  • no Node, account, certificate or server
  1. 1

    Give this build a permanent home

    Brave and Chrome reload an unpacked extension from the exact folder it was loaded from on every start, so a temporary download breaks the first time you tidy up. Keep the clone — or the extracted chrome-web-store.zip — somewhere you intend to keep, then load it from brave://extensions or chrome://extensions with Developer mode on.

  2. 2

    Install the protected watchdog not yet

    Open PowerShell as administrator in that same folder and run it once. whoami prints the account to protect; separate several with commas to cover more than one Windows user. 

    Set-ExecutionPolicy -Scope Process Bypass
.\scripts\install-windows-watchdog.ps1 -ProtectedWindowsUser 'you'
    • copies the watchdog to C:\Program Files\Lock In;
    • registers Lock In Watchdog as an automatic SYSTEM task that restarts itself;
    • creates disabled outbound firewall rules for the installed Brave and Chrome executables; and
    • starts safely disarmed, importing the zones you already have.

    From the release bundle windows-watchdog.zip the same script sits at the root, as .\install-windows-watchdog.ps1.

  3. 3

    Let it arm itself not yet

    Reload the extension. The panel at the top of this page moves from disconnected, to connected · waiting to arm, to Windows enforcement armed after three valid heartbeats. Each protected account's sensor is tracked on its own, so one Windows user cannot cover for a missing sensor in another.

Ways back out 🐭

From an elevated PowerShell window in the same folder:

.\scripts\disarm-windows-watchdog.ps1
stops enforcing now and leaves everything installed.
.\scripts\uninstall-windows-watchdog.ps1
removes the task, the rules and the installed copy. Add -PurgeData to erase configuration and usage as well.
.\scripts\update-windows-watchdog.ps1
replaces the watchdog in place, keeping its rules, usage and armed state.

Lock In removes only registry values it recorded as its own, and all of its firewall rules carry the group name LockInWatchdog. This is still a self-control tool rather than protection from a determined administrator: anyone who can approve a UAC prompt can unregister the task. Browsing from an account that is not the administrator is what makes that boundary real.
