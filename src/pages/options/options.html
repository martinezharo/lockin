local data, clearly explained

Lock In needs limited browsing activity to provide its site-blocking and daily-allowance features.

  • It reads the hostname of the active tab and, when it matches a configured URL rule, its path, query, and fragment, never page content.
  • It stores your zones, schedules, and usage totals in the protected local Lock In watchdog.
  • Nothing is transmitted, sold, shared, or used for advertising or profiling.

No browsing data is handled until you choose Accept and continue. Read the full privacy policy.

super-strict mode, start to finish

Lock In is a dashboard and a sensor: it draws your day and watches the active tab, but nothing outside the browser is stopping you until the Windows app is installed. The installer moves every decision to a Windows service the browser cannot switch off — no terminal, no commands, one UAC prompt.

  • Scheduled zones and spent allowances become Brave/Chrome URLBlocklist policy, applied by Windows rather than by the extension.
  • Always-allowed pages stay open through the matching URLAllowlist and never spend allowance.
  • If the browser is running and the sensor disappears for a minute, every enabled zone is blocked and that account's browser loses outbound network access until Lock In reports back. Other accounts keep theirs.
  • Application zones are tracked from the foreground window and closed by the tray app when their gates are shut.
  • Zones, usage and enforcement state move to C:\ProgramData\LockIn, owned by SYSTEM. Only the Windows accounts you name can configure them.
  • Windows 10 or 11
  • Brave or Chrome
  • one UAC prompt
  • no terminal, account, certificate or server
  1. 1

    Run the Lock In installer not yet

    Download LockIn-Setup.exe from the latest release and double-click it. Windows asks for administrator rights once; tick the local Windows accounts to protect and continue. There is no terminal and nothing to type.

    • installs the Lock In service, which owns zones, schedules, allowances and fail-closed enforcement;
    • installs the Lock In tray app for every protected account and starts it at logon;
    • installs the WebView2 runtime if it is missing;
    • migrates any existing Lock In data and removes the old scheduled task; and
    • starts safely disarmed, importing the zones you already have.
  2. 2

    Install the browser extension checking…

    The extension is the precise sensor for Chrome and Brave: it sees the exact page, path, query and #fragment. Once the Chrome Web Store serves a watchdog-compatible version the installer force-installs it; until then, load it by hand:

    • extract lock-in-chrome-web-store.zip into a folder you intend to keep;
    • open brave://extensions or chrome://extensions;
    • turn on Developer mode and choose Load unpacked; and
    • select the extracted folder.

    The tray app notices when a browser has no Lock In sensor and offers to open the extensions page for you. Its notifications also say when a zone is blocked by schedule or when the extension's sensor is missing.

  3. 3

    Let it arm itself not yet

    Reload the extension. The panel at the top of this page moves from disconnected, to connected · waiting to arm, to Windows enforcement armed after three valid heartbeats. Each protected account's sensor is tracked on its own, so one Windows user cannot cover for a missing sensor in another.

Ways back out 🐭

Everything below lives in Windows, not in a terminal:

Lock In Emergency Disarm — Start menu, or the tray menu
stops enforcing now, with one UAC prompt, and leaves everything installed.
Windows Settings → Apps → Lock In → Uninstall
disarms first, then removes the service, the tray app and Lock In's own registry values and firewall rules. Choose whether to keep or erase the local data.
Run a newer LockIn-Setup
updates in place, keeping zones, usage and protected accounts.
The tray app
shows status and notifications and opens the dashboard; the service starts it again if it is killed.

Lock In removes only registry values it recorded as its own, and all of its firewall rules carry the group name LockInWatchdog. This is still a self-control tool rather than protection from a determined administrator: anyone who can approve a UAC prompt can unregister the task. Browsing from an account that is not the administrator is what makes that boundary real.
